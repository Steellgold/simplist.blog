# Error Handling

The Simplist API uses conventional HTTP status codes and returns detailed error information in JSON format to help you identify and resolve issues quickly.

## Error Response Format

All errors follow a consistent JSON structure:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error description",
    "details": {} // Optional additional context
  }
}
```

## HTTP Status Codes

| Status Code | Description |
|-------------|-------------|
| `200` | Success - Request completed successfully |
| `400` | Bad Request - Invalid request parameters |
| `401` | Unauthorized - Invalid or missing API key |
| `403` | Forbidden - Insufficient permissions |
| `404` | Not Found - Resource doesn't exist |
| `429` | Too Many Requests - Rate limit exceeded |
| `500` | Internal Server Error - Something went wrong on our end |
| `503` | Service Unavailable - Temporary service disruption |

## Common Error Codes

### Authentication Errors

#### `UNAUTHORIZED`

Invalid or missing API key.

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Invalid API key"
  }
}
```

**Solution**: Verify your API key is correct and included in the `X-API-Key` header.

#### `API_KEY_EXPIRED`

The API key has expired.

```json
{
  "error": {
    "code": "API_KEY_EXPIRED",
    "message": "API key has expired"
  }
}
```

**Solution**: Create a new API key in your project settings.

#### `FORBIDDEN`

API key lacks required permissions.

```json
{
  "error": {
    "code": "FORBIDDEN",
    "message": "API key does not have required permission: read"
  }
}
```

**Solution**: Update the API key permissions in your project settings.

### Rate Limiting Errors

#### `RATE_LIMIT_EXCEEDED`

Monthly API call quota exceeded.

```json
{
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Monthly API call quota exceeded. Upgrade to PRO for higher limits.",
    "resetAt": "2024-02-01T00:00:00.000Z"
  }
}
```

**Solution**: Wait until the reset date or upgrade to a higher tier.

#### `TOO_MANY_REQUESTS`

Too many requests in a short time period (IP-based rate limiting).

```json
{
  "error": {
    "code": "TOO_MANY_REQUESTS",
    "message": "Rate limit exceeded. Please slow down your requests."
  }
}
```

**Solution**: Implement exponential backoff and reduce request frequency.

### Resource Errors

#### `NOT_FOUND`

The requested resource doesn't exist.

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Article with slug 'non-existent' not found"
  }
}
```

**Solution**: Verify the resource identifier (slug, ID) is correct.

#### `ARTICLE_NOT_PUBLISHED`

Article exists but is not published.

```json
{
  "error": {
    "code": "ARTICLE_NOT_PUBLISHED",
    "message": "Article is not published"
  }
}
```

**Solution**: Only published articles are accessible via the public API.

### Validation Errors

#### `VALIDATION_ERROR`

Request parameters failed validation.

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": {
      "page": "Must be a positive integer",
      "limit": "Must be between 1 and 100"
    }
  }
}
```

**Solution**: Check the `details` field for specific validation failures.

### Server Errors

#### `INTERNAL_ERROR`

Unexpected server error.

```json
{
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "An unexpected error occurred"
  }
}
```

**Solution**: Retry the request. If the problem persists, contact support.

## Error Handling Best Practices

### 1. Always Check Status Codes

```typescript
const response = await fetch('https://api.simplist.blog/v1/articles', {
  headers: { 'X-API-Key': apiKey }
});

if (!response.ok) {
  const error = await response.json();
  console.error(`API Error: ${error.error.code}`, error.error.message);
  throw new Error(error.error.message);
}

const data = await response.json();
```

### 2. Implement Retry Logic

```typescript
async function fetchWithRetry(
  url: string,
  options: RequestInit,
  maxRetries = 3
): Promise<Response> {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url, options);

      // Don't retry client errors (4xx)
      if (response.status >= 400 && response.status < 500) {
        return response;
      }

      // Success or server error that we can retry
      if (response.ok || i === maxRetries - 1) {
        return response;
      }

      // Wait before retrying (exponential backoff)
      await new Promise(resolve =>
        setTimeout(resolve, Math.pow(2, i) * 1000)
      );
    } catch (error) {
      if (i === maxRetries - 1) throw error;
    }
  }

  throw new Error('Max retries exceeded');
}
```

### 3. Handle Specific Error Codes

```typescript
async function getArticle(slug: string, apiKey: string) {
  const response = await fetch(
    `https://api.simplist.blog/v1/articles/${slug}`,
    { headers: { 'X-API-Key': apiKey } }
  );

  if (!response.ok) {
    const error = await response.json();

    switch (error.error.code) {
      case 'NOT_FOUND':
        return null; // Article doesn't exist

      case 'ARTICLE_NOT_PUBLISHED':
        console.warn('Article exists but is not published');
        return null;

      case 'RATE_LIMIT_EXCEEDED':
        throw new Error('API quota exceeded');

      case 'UNAUTHORIZED':
        throw new Error('Invalid API key');

      default:
        throw new Error(`API Error: ${error.error.message}`);
    }
  }

  return await response.json();
}
```

### 4. Use Type Guards (TypeScript)

```typescript
interface ApiError {
  error: {
    code: string;
    message: string;
    details?: Record<string, string>;
  };
}

function isApiError(data: unknown): data is ApiError {
  return (
    typeof data === 'object' &&
    data !== null &&
    'error' in data &&
    typeof (data as ApiError).error.code === 'string'
  );
}

// Usage
const response = await fetch(url, options);
const data = await response.json();

if (isApiError(data)) {
  console.error(`Error: ${data.error.code}`, data.error.message);
}
```

### 5. Log Errors for Debugging

```typescript
async function apiRequest(url: string, options: RequestInit) {
  try {
    const response = await fetch(url, options);

    if (!response.ok) {
      const error = await response.json();

      // Log error details
      console.error('API Error:', {
        status: response.status,
        code: error.error.code,
        message: error.error.message,
        url,
        timestamp: new Date().toISOString()
      });

      throw new Error(error.error.message);
    }

    return await response.json();
  } catch (error) {
    console.error('Request failed:', error);
    throw error;
  }
}
```

## Using the SDK

The [@simplist.blog/sdk](/sdk) handles errors automatically and provides TypeScript types:

```typescript
import { SimplistClient } from '@simplist.blog/sdk';

const client = new SimplistClient({ apiKey: process.env.SIMPLIST_API_KEY });

try {
  const article = await client.articles.get('my-article');
} catch (error) {
  if (error instanceof Error) {
    console.error('Failed to fetch article:', error.message);
  }
}
```

<Callout type="info">
The SDK automatically retries failed requests and provides better error messages out of the box.
</Callout>

## Need Help?

If you encounter persistent errors:

1. Check the [Status Page](https://status.simplist.blog) for service issues
2. Review your API key permissions
3. Verify your subscription tier and quota
4. Contact support with the error code and timestamp
