# Authentication

All Simplist API requests require authentication using an API key. API keys are project-specific and can be created in your project settings.

## API Keys

Simplist uses a unified API key system with granular permissions. All API keys start with the `prj_` prefix.

```bash
X-API-Key: prj_1234567890abcdef
```

<Callout type="warn">
**Never expose API keys with sensitive permissions in client-side code, version control, or public repositories.** Choose appropriate permissions based on your use case.
</Callout>

## Permission-Based Access

When creating an API key, you select which permissions it should have. This allows you to create keys with only the access they need:

### Available Permissions

| Permission | Description | Use Case |
|-----------|-------------|----------|
| `read` | Read articles and project data | Server-side apps, SSG/SSR, content fetching |
| `analytics` | Track page views and events | Client-side tracking, analytics scripts |
| `write` | Create and update content | CMS integrations *(Coming soon)* |
| `admin` | Full project access | Automation, admin tools *(Coming soon)* |

### Permission Examples

**Read-Only API Key** (Content fetching):
```typescript
// Perfect for server-side rendering or static site generation
const client = new SimplistClient({
  apiKey: 'prj_...' // Has "read" permission only
})
```

**Analytics-Only API Key** (Client-side tracking):
```typescript
// Safe to use in client-side code
const client = new SimplistClient({
  apiKey: 'prj_...' // Has "analytics" permission only
})
```

**Multi-Permission API Key** (Full-featured apps):
```typescript
// Can both fetch content and track analytics
const client = new SimplistClient({
  apiKey: 'prj_...' // Has both "read" and "analytics" permissions
})
```

<Callout type="info">
You can select multiple permissions when creating an API key. Choose only the permissions your application needs to follow the principle of least privilege.
</Callout>

## Authentication Header

Pass your API key in the `X-API-Key` header with every request:

<Tabs items={['cURL', 'JavaScript', 'TypeScript']}>
<Tab value="cURL">
```bash
curl https://api.simplist.blog/v1/articles \
  -H "X-API-Key: prj_your_api_key_here"
```
</Tab>
<Tab value="JavaScript">
```javascript
fetch('https://api.simplist.blog/v1/articles', {
  headers: {
    'X-API-Key': 'prj_your_api_key_here'
  }
})
  .then(res => res.json())
  .then(data => console.log(data));
```
</Tab>
<Tab value="TypeScript">
```typescript
const response = await fetch('https://api.simplist.blog/v1/articles', {
  headers: {
    'X-API-Key': process.env.SIMPLIST_API_KEY as string
  }
});

const data = await response.json();
```
</Tab>
</Tabs>

## Creating API Keys

1. Navigate to your project settings
2. Go to **API Keys** section
3. Click **Create API Key**
4. Choose the key type (Secret or Public)
5. Select permissions
6. Copy the key immediately (it won't be shown again)

<Callout type="warn">
API keys are only displayed once upon creation. Store them securely in environment variables or a secrets manager.
</Callout>

## Best Practices

### Use Environment Variables

Never hardcode API keys in your application:

```bash title=".env"
SIMPLIST_API_KEY=prj_your_secret_key_here
```

```typescript
const apiKey = process.env.SIMPLIST_API_KEY;
```

### Rotate Keys Regularly

For security, rotate your API keys periodically:

1. Create a new API key
2. Update your application to use the new key
3. Delete the old key once no longer in use

### Use Appropriate Permissions

- **Server-side**: Use keys with `read` permission for fetching content
- **Client-side**: Use keys with `analytics` permission only for tracking
- **Full-stack apps**: Use keys with both `read` and `analytics` permissions when needed

### Monitor Usage

Track API key usage in your project dashboard:
- Last used timestamp
- Total requests made
- Remaining quota

## Key Expiration

API keys can optionally have an expiration date. Expired keys will be automatically rejected with a `401 Unauthorized` error.

<Callout type="info">
Keys without an expiration date remain valid until manually deleted.
</Callout>

## Quota Limits

API keys are subject to your project's subscription tier limits:

- **STARTER**: 1,000 API calls per month
- **PRO**: 500,000 API calls per month

When quota is exceeded, requests will return a `429 Too Many Requests` error. See [Rate Limiting](/api/rate-limiting) for details.

## Error Responses

Common authentication errors:

```json title="401 Unauthorized - Invalid Key"
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Invalid API key"
  }
}
```

```json title="401 Unauthorized - Expired Key"
{
  "error": {
    "code": "API_KEY_EXPIRED",
    "message": "API key has expired"
  }
}
```

```json title="403 Forbidden - Insufficient Permissions"
{
  "error": {
    "code": "FORBIDDEN",
    "message": "API key does not have required permission: read"
  }
}
```
